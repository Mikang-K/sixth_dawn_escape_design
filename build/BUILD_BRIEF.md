# BUILD_BRIEF — 전체 동작 후보

작성일: 2026-11-03 · 사용자 후속 요청: 게임 구현 및 검증

## 목표와 경계

- `targetFinish: graybox` — PRODUCT_BRIEF의 다음 제작 목표 유지.
- `buildStage: production` — 이 단계명은 전체 기능 후보를 뜻한다. 상용 출시 품질을 판정한 뜻이 아니다.
- `buildPath: custom` — 유량·광선·좌표·투영·주기 장치를 각각 구현.
- `experienceProfile: system-led`, `signature_command: N/A`.
- 입력: [기획서](../design/GAME_DESIGN.md), [아트 방향](../design/ART_DIRECTION.md), [퍼즐 상세](../README.md#퍼즐-상세).
- 대상: PC 가로 화면의 로컬 브라우저. 기본1280×720, 마우스·키보드. 1인, 한국어. 네트워크 서비스·계정·API 키 없음.

초기 브리프는 엔진과 실행 환경을 잠그지 않았다. 후속 구현에서 Node 정적 서버와 브라우저 Canvas·DOM을 선택했다. 사용할 수 없는 지정 엔진을 웹으로 바꾼 대체판은 아니다. 네이티브 배포 패키지는 범위에 넣지 않았다.

## 보존한 경험

접수대2문제 → 두 방씩 열리는 회랑 → 테마6방 각3문제 → 최종3장치 → 실제 문 개방 → 기록 보존/반환 선택. 필수23개와 선택6개를 모두 실제 입력으로 수행한다.

장치 조작은 상태를 바꾸며, 결과 판정이 화면보다 우선한다. 잘못된 배치가 해결 사실을 올리지 않는다. 규칙판은 한 번만 획득하고 해결한 장치를 초기화해도 전체 진행은 취소되지 않는다. 선택 기록과 힌트 사용은 필수 엔딩 관문이 아니다.

수첩의 원문·규칙판·핀3개·힌트3단계, 미해결 장치 설정 유지, 되돌림, 현재 장치 초기화, 자동 저장·별도 수동 저장, 마지막 선택대 저장, 글자 확대·저동작·음소거·조사 윤곽을 제공한다.

## 구현 구조와 인과

| 부분 | 책임 |
|---|---|
| game/src/content.js | 한국어 단서·힌트·방·목표와 선행 관계 |
| game/src/model.js | 유효 설정, 수리·논리·기하 판정, 관문, 실제 처리, 저장 복원 |
| game/src/widgets.js | 장치별 입력과 계산 상태의 시각화 |
| game/src/scenes.js | 독창적인 도트 공간과 복구 후 상태 |
| game/src/pixel-art.js | 정수 픽셀 래스터, 재질별 소품, 캐릭터·항구 원본 |
| game/src/main.js | 플레이 진행, 창·포커스, 수첩·힌트, 저장, 두 엔딩 |
| game/server.mjs | 현재 컴퓨터 전용 정적 서버. 게임 실행 자산만 제공 |
| game/tests | 기획서에서 전사한 독립 정답 후보와 실제 브라우저 입력 |

무작위 정답과 실시간 강제 타이머는 없다. 미확인 수신·실제 인도·확인 수령을 구분한다. 단서는 읽어야 수첩에 남지만 관찰 플래그를 숨은 정답 자격으로 쓰지 않는다. 저장은 버전·장치별 값·선행 관계를 확인해 복원한다. 이전 버전의 실제 게임 저장은 없어 마이그레이션은 구현하지 않았다.

## 실행 환경과 명령

| 항목 | 실제 값 |
|---|---|
| targetPlatform | PC |
| targetRuntime | 로컬 HTTP에서 실행하는 데스크톱 브라우저 |
| testedRuntime | Windows, Playwright Chromium156.0.8078.4 |
| engine | 자체 ES modules + Canvas 2D + HTML 장치 |
| engineVersion | 게임1.1.0 |
| runtimeVersion | Node24.18.1 |
| packageManager | npm11.16.0 |
| test dependency | @playwright/test1.64.1, 앱 런타임 의존성 없음 |

게임 폴더를 작업 디렉터리로 사용한다.

```powershell
# 플레이: 패키지 설치 없이
node server.mjs

# 검증 도구를 새로 설치하는 환경에서만
npm.cmd ci
npx.cmd playwright install chromium

# 판정 검사, 실행 묶음, 권위 검증
npm.cmd test
npm.cmd run build
npm.cmd run verify
```

`start`: http://127.0.0.1:4176. `buildOrExport`: game/dist. `verify`: npm.cmd run verify. `modelCheck`: npm.cmd test 및 기획 폴더의 python -X utf8 validation/verify_puzzles.py.

## 검증과 증거

검증 담당 절차: `game-qa`. 기준 사실원은 [game/qa/verification.json](../game/qa/verification.json) 하나다. 여기에는 권위 명령의 종료 코드, 여섯 필수 검사, 완주 실행 ID와 한계를 기록한다. 실제 입력·환경·관찰은 [run.json](../game/qa/evidence/run.json), 실제 화면은 해당 파일이 가리키는 PNG다.

같은 빈 브라우저 컨텍스트에서 시작 → 실제 입력 → 29개 장치 → 보존 결말 → 새 기록의 접수대까지 잇는다. 별도 경로에서 선택6개 생략·반환 결말·마지막 선택 복원을 확인한다. 실제 Tab/Shift+Tab·Esc, 글자 확대, 저장·힌트·핀·되돌림, 오답도 함께 검사한다. 숨은 해결 플래그를 직접 쓰는 테스트 훅은 없다.

확인한 화면: 제목, 온실 분배, 극장 투영, 최종 광선·투영, 보존/반환 결과, 재시작. 캐릭터·황동·종이·남색 공간·상태 후의 표시라는 아트 계약을 도트 회색상자 수준에서 반영했다. 사전 승인된 원화 목표 이미지는 없으므로 원화와 픽셀 단위 비교를 했다고 주장하지 않는다.

v1.1에서는 위 방향을 이어가며 도트 미술을 고도화했다. 동일 상태20개를 비교했고, 정상 진행 중 공용 공간·각 방·출구의 실제 UI도 다시 캡처했다. [미술 검토](../design/VISUAL_REVIEW.md)와 [전후 갤러리](../game/qa/art-review.html)를 참고한다. 고정 미술 프레임과 실제 플레이 증거는 구분하며 현재 게임 빌드의 해시는 게임 검증 증거에 기록된다.

## 표현 범위와 남은 검증

- 공간의 물품은 장치 안에서 선택·배치한다. 범용 인벤토리와 드래그 인터페이스는 두지 않는다. 장치마다 키보드 대체 입력이 있다.
- 배경은 직접 그린 절차적 도트, 장치 확대면은 읽기 좋은 도형과 HTML이다. 최종 판매용 도트 자산·환경 음악·성우·별도 영상 컷신은 없다. 장치음은 합성 피드백이며 청각적 품질 평가는 하지 않았다.
- 되돌림 이력은 실행 중에만 쌓인다. 새로고침 후에도 현재 설정·진행·힌트·핀은 저장에서 복원된다.
- 전체 입력 순서의 수학적 무교착, 첫 방문자의 발견 가능성·재미·난도·4~6시간 목표, 다른 브라우저·실제 스크린리더·네이티브 배포·장시간 성능은 미검증.
- 현재 검증 결과를 예전 초안이나 이후 변경 버전의 결과로 바꾸어 인용하지 않는다. 실행 자산의 해시는 완주 증거의 환경에 함께 기록했다.
