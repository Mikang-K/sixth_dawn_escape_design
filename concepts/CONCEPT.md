# CONCEPT — 여섯 번째 새벽: 폐관 기록

입력: [PRODUCT_BRIEF](../PRODUCT_BRIEF.md), [SOURCE_BIBLE](../analysis/SOURCE_BIBLE.md). 두 문서를 먼저 작성한 뒤 이 단계에 사용했다. `game-concept`의 역할은 방향 선택까지로 제한하고, 상세 퍼즐은 후속 세계 설계에 둔다.

## 1. 고정값과 비교할 차원

사용자 고정값은 도트 그래픽·방탈출·다양한 공간·정교한 퍼즐이다. 브리프의 PC·1인·마우스 중심·한국어·4~6시간·필수 23문제·선택 6문제는 이번 버전의 설계 기준이다. 원전은 폐관 전시관, 수첩, 여섯 관리 기록과 출구 기관을 고정한다.

장르와 그림체를 다시 투표하지 않는다. 열려 있는 **진행 구조**만 비교한다. 두 방씩 여는 회랑, 전면 선형 동선, 여섯 방 전면 개방이 실제 교환 조건을 가진 대안이다.

## 2. 경험 약속과 실패 징후

> 방마다 다른 문제를 풀지만, 마지막에는 방이 아니라 규칙을 기억해서 탈출한다.

| 경험 가설 | 플레이에서 관찰할 현상 | 설계가 실패한 징후 |
|---|---|---|
| 관찰이 답을 만든다 | 플레이어가 원문을 핀으로 붙이고 실험 전후를 비교한다 | 소품을 전부 눌러 얻은 숫자만 무작위 대입한다 |
| 다른 공간이 새로운 사고를 요구한다 | 유량·광선·투영·중복 처리에서 다른 가설을 세운다 | 여섯 방이 배경만 바뀐 암호 자물쇠다 |
| 배운 관계가 전이된다 | 최종 장치의 새 배치에 이전 규칙을 적용한다 | 수첩의 정답을 그대로 복사해야만 한다 |
| 실패는 실험이다 | 오답 원인을 보고 하나의 설정을 바꿔 재시도한다 | 단서 손실, 영구 봉쇄, 긴 재생으로 실험을 꺼린다 |

## 3. 사용할 선례 문법

다음은 특정 작품에 대한 사실 비교가 아니라 이미 익숙한 장르 문법의 차용 범위다.

| 문법 | 빌리는 것 | 제외하는 것 |
|---|---|---|
| 방탈출의 관찰→조합→검증 | 장치 확대, 인벤토리, 단서 회수, 탈출 목표 | 픽셀 사냥, 방 밖의 암호 상식, 소모품 교착 |
| 기계 퍼즐의 즉시 시뮬레이션 | 설정 변화의 가시적 반응, 작은 조작 범위 | 장치 내부에서만 통하는 숨은 예외 |
| 허브형 어드벤처 | 열린 방 확인, 재방문, 해결 표시 | 의미 없는 왕복·대사 소진을 통한 관문 |
| 규칙 학습 후 재조합 | 최종부의 새로운 수치와 공간에 적용 | 이전 암호 여섯 개를 다시 입력하기 |

원전이 추가하는 차이는 ‘접수자가 기록의 관계를 복원한다’는 행동 대상과 순서다. 수첩은 획득물을 쌓는 창고보다 관찰의 출처와 전후 관계를 유지하는 도구가 된다. 폐관 기관은 플레이어가 실제로 복원한 여섯 규칙을 읽는다.

## 4. 후보 콘셉트 카드

### A. 두 방씩 열리는 회전 회랑 — 채택

- 주유형: 포인트 앤 클릭 방탈출. `experienceProfile: system-led`.
- 차용/거절: 허브의 재방문과 해결 표시를 차용한다. 무목적 이동과 방을 넘나드는 필수 물품 운반은 제외한다.
- 신분과 반복 행동: 윤서는 접수 절차를 이어받아 기록과 실제 작동을 대조한다. 회랑에서 방을 선택하고, 관찰·실험·복구 뒤 규칙판을 가져온다.
- 핵심 루프: 방 선택 → 단서와 설정 연결 → 장치 실험 → 오류의 관계 수정 → 방 복구 → 회랑의 실제 설비 변화.
- 저항·압력: 한 번에 열린 두 개의 문제 계열. 장치의 제한과 기록 해석이 저항이며 카운트다운은 없다.
- 실패: 설정 불일치가 확대면에 표시된다. 되돌림과 장치 초기화가 가능하다.
- 세계 응답: 방 복구에 따라 회랑의 물·별등·우편 표시가 복구되고 다음 두 문이 열린다.
- `signature_command: N/A`. 물체·배열·버튼 조작으로 충분하다. 자유어 지시가 정체성이나 선택을 늘리지 않는다.
- 원전 긴장의 행동화: ‘보관된 결과’와 ‘실제로 처리된 관계’를 구분하며, 최종 우편 잠금이 중복을 그대로 읽어내지 않도록 복구한다.
- 대표 장면: 앞 방에서 배운 계량과 박자를 다른 형태의 출구 장치에 적용하자 잠긴 금속 핀이 올라간다.
- 최소 검증: 온실의 완전한 한 방과 회랑 귀환, 출구의 온실 모듈까지 연결한다.
- 최대 위험/기각 관찰: 다른 방으로 옮기면 추론이 전부 잊힌다. 핀·해결 상태·원문 복기로도 복귀가 어렵다면 병렬 개방 수를 줄인다.

### B. 여섯 방의 단일 통로

- 주유형·프로필: 같은 방탈출, `system-led`.
- 차용/거절: 선형 퍼즐 투어의 명확한 목표를 차용하고 단일 정체 구간의 강제 반복은 거절한다.
- 신분·행동·루프: 접수자가 정해진 다음 방의 기록을 하나씩 복구한다. 조작 대상은 A와 같지만 방 선택이 사라진다.
- 압력·실패·응답: 현재 한 문제만 남는다. 막히면 힌트 외의 전환 수단이 없고 해결 뒤 바로 다음 문이 열린다.
- `signature_command: N/A`. 원전 긴장은 유지하되 ‘기록들이 하나의 기관을 이룬다’는 공간 감각은 약해진다.
- 대표 장면/최소 검증: 온실 전체를 통과해 다음 방문으로 나오는 경로.
- 최대 위험/기각 관찰: 한 문제 정체가 전체 이탈로 이어진다. 내용 비용은 낮지만 본작의 실험 편의를 충분히 주지 못하면 채택하지 않는다.

### C. 여섯 방 전면 개방

- 주유형·프로필: 같은 방탈출, `system-led`.
- 차용/거절: 자유 탐색과 자율적 문제 전환을 차용하고 외부 공략을 전제로 한 암호 추적은 제외한다.
- 신분·행동·루프: 접수자가 여섯 기록을 원하는 순서로 복구한다. 조작 대상은 A와 같고 모든 방을 언제든 선택한다.
- 압력·실패·응답: 자유도 대신 동시 미해결 가설이 늘어난다. 해결한 방만 국소 복구되고 출구는 여섯 판을 기다린다.
- `signature_command: N/A`. 순서보다 기록의 독립성을 강조하는 방향이다.
- 대표 장면/최소 검증: 서로 다른 여섯 문을 골라 실험한 뒤 하나를 끝내는 경로. 이 자유도를 평가하려면 방 하나보다 많은 내용이 먼저 필요하다.
- 최대 위험/기각 관찰: 단서의 소속을 기억하지 못해 수첩 검색이 주된 일이 된다. 최소 검증의 콘텐츠 부담이 가장 높다.

## 5. 하드 기각과 결정

| 기각 기준 | A | B | C |
|---|---|---|---|
| 조작과 관찰 가능한 세계 변화가 닫힌 루프를 이루는가 | 충족 | 충족 | 충족 |
| 원전의 기록·관계 복원이 반복 행동에 있는가 | 충족 | 충족 | 충족 |
| 이름을 지워도 대상·순서·응답에 고유한 차이가 있는가 | 관계 전이 | 역복구 | 관계망 탐색 |
| 최소 검증이 브리프 안에서 가능한가 | 한 방+연결 모듈 | 한 방 | 여섯 방 일부를 먼저 요구, 비용 위험 |
| 타 작품 자산·서비스 복제를 전제로 하는가 | 아니오 | 아니오 | 아니오 |
| 텍스트 증가 외에 실제 장치 변화가 있는가 | 있음 | 있음 | 있음 |
| 실제 조작을 세계가 읽는가 | 읽음 | 읽음 | 읽음 |

세 방향 모두 현 단계에서 하드 기각 사유는 없다. A는 B보다 회랑과 병렬 상태 표시가 필요하지만 정체 시 전환 수단이 있다. C보다 동시 기억 부담과 첫 검증 비용이 작다. 인위적 합산 점수 없이 이 교환 조건으로 A를 선택한다.

선택 상태: `quick / selected / A`. 사용자가 이미 지정한 방탈출·도트 방향은 다시 선택 대상으로 삼지 않았다.

## 6. 플레이어의 권한과 양보하지 않을 약속

플레이어는 열린 방의 방문 순서, 장치 설정과 실험 순서, 힌트 열람, 선택 기록 회수, 마지막 기록 처리 방식을 결정한다. 장치는 조건이 맞을 때만 결과를 확정하며 수첩이 대신 정답을 제출하지 않는다.

필수 규칙은 각 방 안에서 발견한다. 선택 기록은 주체와 출처를 더해도 필수 단서를 독점하지 않는다. 틀린 시도 때문에 방을 잃지 않는다. 최종부에는 새로운 추론 규칙을 갑자기 추가하지 않는다.

서사 구조는 공통 동선에 짧은 회수 장면이 붙는 재합류 구조다. 두 엔딩 장면과 선택 기록 6개의 짧은 삽입 장면을 한 번씩 제작한다. 숨은 선악 점수나 64개 조합별 엔딩은 두지 않는다.

## 7. 최소 검증 질문과 열린 문제

- 유량·박자를 글 설명 없이도 조작 화면에서 읽을 수 있는가? 온실 회색상자로 확인한다.
- 장치 초기화가 해결한 하위 문제와 수첩을 지키는가? 저장 복원 구현 때 확인한다.
- 앞 방과 다른 장치에 배운 관계를 적용할 수 있는가? 출구 모듈의 새 배치로 확인한다.
- 두 방 병렬 구조가 부담을 줄이는가? 첫 두 방 관찰로 확인한다.
- 최종부의 공간 정렬은 텍스트 모형만으로 검증할 수 없다. 광선과 원근을 조작할 수 있는 별도 회색상자가 필요하다.

미정: 최종 배포 플랫폼, 엔진, 실제 난이도와 플레이타임, 제작 인원과 일정, 최종 도트 자산. 미정을 결정하기 위해 현재 기획 범위를 넓히지 않는다.
