# 여섯 번째 새벽: 폐관 기록

**여섯 방에서 배운 규칙으로 마지막 문을 여는 도트 그래픽 방탈출 게임 기획서.**

폐관 전시관에서 깨어난 접수자 윤서는 기록보관소·침수 온실·야간 천문대·종이 인형극장·무인 우편 교환국·시계 공방을 복구한다. 마지막에는 숫자 암호 여섯 개를 다시 입력하는 대신, 앞에서 이해한 순서·양·시선·투영·중복·주기를 새로운 출구 장치에 적용한다.

작성: 2026-11-03 · 버전 v1.0 · 한국어 · 독창적 설정

## 게임 구현본

후속 요청에 따라 전체 퍼즐을 연결한 로컬 브라우저 게임을 만들었다. **[플레이 안내](game/README.md)** · **[게임 열기](http://127.0.0.1:4176)** · **[Windows 시작 파일](game/START_GAME.cmd)**.

필수23개·선택6개, 수첩·핀·힌트·저장·두 엔딩을 포함한다. 최종 미술 이전의 도트 회색상자이며 현재 검증 기준은 **[게임 검증 JSON](game/qa/verification.json)** 과 **[빌드 계약](build/BUILD_BRIEF.md)** 이다. 아래 기획 문서에는 정답과 결말이 공개되어 있다.

그래픽 고도화 **v1.1**: 방별 재질·조명·창밖 항구·캐릭터·장치 패널을 개선했다. **[변경 전·후 갤러리](game/qa/art-review.html)** 와 **[미술 검토](design/VISUAL_REVIEW.md)** 에서 동일한 상태를 비교할 수 있다.

## 먼저 읽기

1. **[게임 기획서 본문](design/GAME_DESIGN.md)** — 전체 경험, 진행, 조작, 실패, 힌트, 이야기와 첫 제작 범위.
2. **[퍼즐 상세](#퍼즐-상세)** — 필수23개·선택6개의 단서 원문, 조작 범위, 풀이, 정답, 오답 피드백, 힌트3단계, 복구와 보상.
3. **[도트 아트 방향](design/ART_DIRECTION.md)** — 방별 시각 차이, 화면 구성, 단서 가독성, 음향과 저동작 대체.
4. **[퍼즐 연결도](design/PUZZLE_DEPENDENCIES.md)** · **[풀이 검증 결과](validation/VALIDATION_REPORT.md)** · **[제작·플레이테스트 계획](production/PLAYTEST_PLAN.md)**.

기획 문서는 게임 제작자를 위한 내용이므로 정답과 이야기의 마지막까지 공개한다. 실행 가능한 후보는 별도의 game 폴더에 있으며 최종 원화·환경 음악은 포함하지 않는다.

## 기획 한눈에 보기

| 항목 | 기본안 |
|---|---|
| 장르 | 1인 포인트 앤 클릭 방탈출 |
| 화면 | 2D 도트, PC 가로 화면, 마우스 중심·키보드 대체 조작 |
| 분위기 | 젖은 종이·황동·남색 새벽의 초현실 미스터리, 추격·유혈 없음 |
| 진행 | 두 방씩 병렬 개방하는 회전 회랑 → 최종 장치3개 |
| 분량 | 첫 플레이4~6시간 목표, 실제 시간 미검증 |
| 퍼즐 | 필수23개 + 선택6개 = 29개 |
| 실패 | 필수 소모품 손실 없음, 장치별 되돌림·초기화 |
| 도움 | 원문 수첩·핀 비교·상호작용 윤곽·힌트3단계 |
| 결말 | 탈출 뒤 공용 보존/개인 반환2종, 힌트 사용으로 불이익 없음 |

플랫폼·플레이타임·배경과 세부 구조는 미지정 부분을 완결하기 위한 기획 가정이다. 사용자 확정 요구와 구분한 표는 [PRODUCT_BRIEF](PRODUCT_BRIEF.md)에 있다.

## 스킬 적용과 문서의 출처

`game-concept`은 `SOURCE_BIBLE`과 `PRODUCT_BRIEF`를 먼저 요구한다. 외부 원작을 제공받지 않았으므로 이번 요청의 창작 작업으로 원전·요구사항을 먼저 작성하고, 그 문서를 입력으로 사용했다. 콘셉트 단계가 없는 원작을 분석한 것처럼 꾸미지 않는다.

| 순서 | 단계와 적용 | 산출물 |
|---|---|---|
| 1 | 독창적 설정·요구사항 선행 작성 | [원전](source/ORIGINAL_SETTING.md), [브리프](PRODUCT_BRIEF.md), [바이블](analysis/SOURCE_BIBLE.md) |
| 2 | `game-concept` | [열린 진행 구조 비교와 방향 선택](concepts/CONCEPT.md) |
| 3 | `game-world-design` | [게임 규칙](design/GAME_DESIGN.md), [연결도](design/PUZZLE_DEPENDENCIES.md), 퍼즐 상세9문서 |
| 4 | `game-art-direction` | [미술·화면·음향 계약](design/ART_DIRECTION.md) |
| 5 | `ponytail` 최소 구현 원칙 | [Python 표준 라이브러리 풀이 검사](validation/verify_puzzles.py) |

초기에는 위 스킬로 설계 절차를 수행했다. 후속 구현에는 `game-build`와 `game-qa`를 적용했으며, 상용 출시 절차는 수행하지 않았다.

## 검증과 한계

기획 폴더에서 다음 명령으로 수치·도형·기호와 선행 관계를 재검사한다. 추가 패키지는 필요 없다.

```powershell
python -X utf8 validation/verify_puzzles.py
```

검사 범위는 명세된 유한 후보에 대한 정답 상태, 동치 입력의 일부 확인, 필수/선택 개수, 선행 관계와 상대 파일 링크다. [실제 실행 결과](validation/VALIDATION_REPORT.md)를 확인한다.

초기 수리 검사는 게임 품질의 증거가 아니다. 후속 게임의 실제 조작·저장·완주·엔딩·재시작 검증 범위는 게임 검증 JSON을 따른다. 모든 상태의 무교착, 초심자의 재미·난도·실제 플레이 시간과 최종 미술 품질은 여전히 검증하지 않았다.
