# 제작 우선순위와 플레이테스트 계획

아래는 초기 기획에서 정한 제작·검증 순서다. 후속 요청으로 실제 후보를 만들었고 현재 결과는 [게임 검증 JSON](../game/qa/verification.json)을 따른다. 이 계획표 자체를 통과 결과로 사용하지 않는다. 인원·일정·비용과 초심자 관찰은 정하지 않았다.

## 1. 먼저 만들 범위

| 순서 | 제작 묶음 | 끝내야 할 관찰 |
|---|---|---|
| 1 | 접수대, 회랑, 수첩, 온실 전체 | 실제 클릭·키보드로 첫 방 전체를 해결하고 귀환 |
| 2 | F-1 전이 검증 장치 | 온실에서 배운 양·때를 다른 모양과 수치에 적용 |
| 3 | 천문대·극장 회색상자 | 광선 경로, 좌표, 깊이와 시점을 조작하며 읽음 |
| 4 | 기록보관소·교환국·공방, 정상 진행 관문 | 조건 문구·중복·역복구가 화면과 실제 처리에 일치 |
| 5 | 최종부 전체, 선택6문제, 엔딩2종 | 모든 필수 경로, 출처 회수, 선택 결과 분리 |
| 6 | 도트 정제·음향·텍스트 다듬기·복원 검사 | 단서 가독성을 보존하면서 의도한 분위기 확보 |

첫 묶음이 직관적이지 않으면 나머지 방의 완성 도트 자산을 일괄 제작하지 않는다. 실패 원인을 밝혀 범례·원문·피드백을 고친 뒤 다시 본다. 주관적 만족을 자동화 스크립트의 통과로 대체하지 않는다.

## 2. 필요한 콘텐츠와 범위 압력

- 전체 공간 보기: 접수대·회랑·테마6방·최종실 = 9개가 기본안.
- 필수 장치: 23개 확대면이 기본안. 같은 재료·조작부는 공유하되 서로 다른 관계를 배경만 바꿔 표현하지 않는다.
- 선택6문제는 기존 확대면의 서랍·악보·사진·저울 안에 넣는다. 별도 복도나 방을 늘리지 않는다.
- 서사: 공통 장면의 짧은 문장, 엔딩2장면, 선택 출처의 짧은 회수6개. 모든 조합별 장면은 쓰지 않는다.
- 그래픽 비용이 가장 큰 것은 서로 다른 여섯 장치의 ‘설정 전후·오답·성공’이다. 포스터 수보다 이 상태의 수를 먼저 센다.

축소가 필요하면 필수 규칙의 학습과 최종 적용을 한 쌍으로 함께 재설계한다. 설명은 삭제하고 최종 관문은 그대로 두는 축소는 하지 않는다. 선택 문제와 배경 연출을 먼저 조정하고, 필수 23/선택6이라는 현재 계약을 바꾸면 문서와 검증 수량도 함께 갱신한다.

## 3. 퍼즐별 정적 검토

1. 단서 원문에 정확한 관계와 범위가 있는가? ‘바로 다음’과 ‘나중’, ‘하나’와 ‘하나 이상’이 섞이지 않는가?
2. 정답 후보의 조작 범위를 화면이 그대로 제공하는가? 문서에는 없는 반전·대각선·실시간 예외가 들어가지 않았는가?
3. 정답 상태와 동치 입력의 범위를 구별했는가? 특히 줄 당기는 순서·우표 위치·기어 중간 순서.
4. 정답에 필요한 단서가 선택 수집·엔딩 조건에 갇히지 않았는가?
5. 수치·좌표·규칙을 바꾸면 [검증 스크립트](../validation/verify_puzzles.py)와 해당 카드, 주 설계 표를 함께 고쳤는가?

현재의 계산 결과는 [검증 보고서](../validation/VALIDATION_REPORT.md)에 한정한다. 자동 검사가 문서의 모든 자연어를 해석해 수학식과 동일성을 증명하는 것은 아니다. 카드와 스크립트의 대응은 사람이 함께 검토해야 한다.

## 4. 첫 사용자 관찰

초심자5명·장르 경험자2명을 소규모로 관찰한다. 숙련도 차이를 적고 평균값 하나로 합치지 않는다. 모두의 무힌트 완주를 성공 기준으로 삼지는 않는다. 힌트가 이해를 돕는지, 직접 해답을 읽었을 때 조작을 수행할 수 있는지도 본다.

| 관찰할 질문 | 기록할 행동·말 | 수정할 위치 |
|---|---|---|
| 첫 목표가 보이는가 | 첫 클릭과 ‘지금 해야 할 일’ 설명 | 첫 화면 구도·목표 문장 |
| 필수 단서를 찾는가 | 관찰 위치·놓친 이유·윤곽 표시 사용 | 단서의 배치·상호작용 영역 |
| 조건을 같은 뜻으로 읽는가 | ‘바로 다음’, 위상0, 정확히3의 해석 | 원문·범례 |
| 오답을 실험으로 쓰는가 | 바꾼 설정과 예상, 실제 피드백 해석 | 상태 표시·불일치 문장 |
| 방 전환 뒤 이어서 생각하는가 | 이전 가설을 복기하는 과정 | 수첩의 원문·핀·설정 유지 |
| 규칙을 새 모양에 적용하는가 | F-1에서 앞방과 연결하는 발언 | 학습 장치·전이 배치 |
| 시선과 좌표가 읽히는가 | 행/열 혼동, 투영의 앞/뒤 오인 | 천문대·극장 확대면 |

관찰자는 실험 중 답을 암시하지 않고 플레이어가 누른 힌트만 제공한다. 막힘 때문에 테스트를 계속할 수 없으면 해답을 제공한 지점과 이유를 적고, 그 이후 구간을 무힌트 성공으로 집계하지 않는다.

공통 기록 항목: 문제 ID, 숙련도, 시작/완료/중단 시점, 핵심 단서 최초 열람, 힌트 단계, 반복 오답, 정답 근거 설명, 조작 불편. 개인정보나 불필요한 화면 녹화는 전제하지 않는다.

## 5. 실제 조작·저장 검증

| 시나리오 | 기대 상태 |
|---|---|
| 각 필수 장치의 명시 정답 입력 | 카드와 같은 상태·다음 기회 |
| 각 카드의 대표 오답 | 같은 원인과 복구 가능 상태 |
| 해결 전 회랑으로 이탈·재입장 | 유효 설정·발견 단서 유지 |
| 실험 도중 메뉴·취소·불러오기 | 물품·인도·물의 소실이나 중복 없음 |
| 우편41 재전송 반복 | 인도1회 유지, 확인 생성만 반복 |
| 성공 직후 제출 연타 | 규칙판1개, 문 열기1회, 다음 관문 유지 |
| 각 장치 초기화 | 해당 시험 상태만 복원, 다른 해결 사실 유지 |
| 두 방 순서를 각각 뒤집어 진행 | 다음 단에 같은 권한으로 도달 |
| 선택 문제 전부 생략 | 필수23개와 두 엔딩 선택 모두 가능 |
| 선택 문제 뒤늦게 회수 | 이미 해결한 필수 장치 재풀이 없이 출처 획득 |
| 키보드만 사용 | 모든 필수 장치와 수첩·힌트 조작 가능 |
| 음소거·저동작·색 구별 없이 보기 | 필수 정보와 실제 결과 구별 |
| 마지막 선택 직전 불러오기 | 양쪽 엔딩의 선택·출처 표기 섞임 없음 |

위 표는 입력·상태를 확인하는 검증이다. 별도로 재미·긴장·이해·반복 피로를 관찰해야 한다.

## 6. 문서를 수정할 근거

- 단서를 열지 못해 막힘: 단서 위치·상호작용 표식을 먼저 수정.
- 읽었지만 다른 뜻으로 이해: 원문과 예시를 수정.
- 맞는 규칙을 말하지만 조작 실패: 클릭/키보드 조작과 눈금을 수정.
- 앞방은 풀었지만 최종 전이 실패: 새로운 규칙을 더하지 말고 학습의 가시적 인과와 비교 도구를 수정.
- 기획상 허용한 다른 순서가 거부됨: 판정 조건을 고치고 동치 입력을 재검증.
- 재미가 없는 반복: 실제로 같은 추론을 반복하는지 확인하고 퍼즐을 교체. 숫자와 소품 이름만 바꾸는 수정은 피함.

문서 수정 후 영향받은 수리 검사와 대표 경로를 다시 수행한다. 이번 버전의 통과 결과를 수정한 버전에 그대로 인용하지 않는다.
